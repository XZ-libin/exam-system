# 在线考试系统 · 开发计划书

课题序号：6
技术栈：SpringBoot + MySQL + Vue3
数据库表要求：≥ 5 张（本方案 12 张表 + 2 个视图）
交付方式：全程 Docker 容器内运行 + 浏览器实测验收

---

## 1. 项目定位与交付物

| 项 | 内容 |
| --- | --- |
| 目标 | 一套可运行、可演示、可答辩的在线考试系统，覆盖任务书 7 个功能模块 |
| 使用者 | 管理员（系统/用户）、教师（题库/试卷/考试/阅卷/统计）、学生（答题/成绩） |
| 代码交付 | 单仓库 `exam-system/`：`backend/`（SpringBoot）+ `web/`（Vue3）+ `db/`（SQL）+ `docker/` |
| 文档交付 | 需求说明书、ER 图、数据库字典、接口清单、部署运行说明、功能截图、演示账号表 |
| 演示数据 | `db/01_schema.sql` + `db/02_seed.sql`：3 角色 × 若干用户、2 门科目、≥ 40 道题（5 种题型）、2 套试卷、1 场已结束考试含 5 份已判分答卷 |
| 一键运行 | `docker compose up -d --build` 后浏览器访问 `http://localhost:8080` |

## 2. 需求分析

### 2.1 角色与权限矩阵

| 功能 | 管理员 | 教师 | 学生 |
| --- | --- | --- | --- |
| 登录 / 改密 / 个人资料 | ✓ | ✓ | ✓ |
| 用户与角色管理（增删改、禁用、重置密码） | ✓ | ✗ | ✗ |
| 题库分类维护 | 全部 | 自建 + 授权 | ✗ |
| 题目维护 / 批量导入 | 全部 | ✓ | ✗ |
| 试卷组卷 / 预览 | 全部 | ✓ | ✗ |
| 考试发布 / 强制收卷 / 成绩发布 | 全部 | ✓ | ✗ |
| 主观题阅卷 | ✗ | ✓ | ✗ |
| 在线答题 | ✗ | 可模拟 | ✓ |
| 成绩查询 | 全部 | ✓ | 本人 |
| 统计分析 | ✓ | ✓ | 本人学习分析 |

### 2.2 七大模块拆解（对齐任务书）

**① 用户中心**
- 账号密码登录（JWT）、退出、Token 续期与失效跳转
- 管理员新建/导入用户（学号即登录名）、禁用启用、角色分配、密码重置
- 学生自助：改密码、改头像/手机/邮箱
- 个人中心查看我的班级、我的考试、我的成绩概览

**② 题库管理**
- 分类树：科目 → 章节，两级以上，支持无限级 `parent_id`
- 5 种题型：单选、多选、判断、填空、简答
- 题目字段：题干、选项（JSON）、正确答案、分值、难度 1–5、解析、状态
- 检索：按分类 + 题型 + 难度 + 关键字 + 创建人 组合筛选，分页
- 批量录入（粘贴文本按约定格式解析）+ Excel/CSV 导入模板
- 引用统计：题目被多少套试卷引用，被引用时禁止硬删（走逻辑删）

**③ 试卷管理**
- 两种组卷方式：
  - 人工组卷：从题库选题加入购物车，逐题设分值与顺序
  - 规则组卷：按「分类 + 题型 × 数量 × 难度分布」自动抽题，可重抽
- 试卷总分自动汇总校验（各题分值之和 = 总分，保存前后端双重校验）
- 试卷状态机：草稿 → 已发布 → 已归档；已发布后题目锁定
- **快照策略**：入卷时把题型、题干、选项、答案、分值写入 `ex_paper_question`，题库后续改动不影响已发布的考试
- 试卷在线预览、按分值打印/导出

**④ 考试管理**
- 场次配置：选试卷、名称、起止时间、答题时长、迟到允许分钟、最大尝试次数
- 参考范围：全部学生 / 指定班级 / 指定名单导入
- 防作弊开关：题目乱序、选项乱序、切屏次数上限（超限自动交卷）
- 状态由时间实时推导：未开始 / 进行中 / 已结束 / 已发布成绩
- 手动操作：提前开始、强制收卷、成绩发布（未发布前学生只看到「已完成」）

**⑤ 在线答题**（技术难点最高，单独设计）
- 进入前校验：是否在参考名单、场次是否进行中、剩余尝试次数
- 服务端权威计时：`record.start_time + duration` 决定死线，前端倒计时只是展示；刷新/换设备从断点续考
- 答题卡：题号网格 + 已答/未答/标记三态，点击跳题
- 答案自动保存：每答一题即时提交 + 30s 心跳批量保存，前端 5s 防抖
- 交卷：主动交卷二次确认；到时后端定时任务强制交卷
- 客观题交卷即判分（多选需全对得分，可配置漏选半分）；主观题进入「待阅卷」队列

**⑥ 成绩管理**
- 自动判分：单选/判断/填空（多答案、忽略大小写与首尾空格、可配是否区分顺序）
- 阅卷台：按试卷 + 题目聚合待阅答案，逐份或批量给分 + 评语，完成后合分
- 成绩单：本人明细（每题作答、正确答案、得分、解析）、教师看全班
- 复核/撤销发布、导出 Excel

**⑦ 统计分析**
- 教师端概览看板：考试数、参考率、平均分、及格率、最高/最低
- 分数段分布（柱状）、每题正确率（横条，定位难题）、班级对比（雷达）
- 试卷质量：难度系数、区分度（高分组 vs 低分组正确率差）
- 学生端：我的成绩趋势折线、各科目正确率、能力雷达、错题本入口

| 层 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| 后端框架 | SpringBoot | 3.2.x | JDK17 起步，学校机房若有 JDK8 约束则整体降级到 2.7.x（见 §10） |

| 定时任务 | Spring `@Scheduled` | - | 超时强制交卷、成绩自动结算 |
| 前端 | Vue 3 + Vite + JavaScript（非 TS） | Vue 3.4+ | `<script setup>` 写法，对齐课堂项目 |

| 图表 | ECharts 5 | - | 统计分析模块，按需引入 |
| HTTP | axios | 封装拦截器 | 统一 `code/message/data`、401 跳登录、错误 toast |
| 构建/运行 | Docker Compose | - | 三容器编排，本机不需要装 JDK/MySQL |

## 4. 系统架构

```
Browser (Vue3 SPA, nginx)
   │  /api/**  反向代理
   ▼
SpringBoot (controller → service → mapper → MySQL)
   │  统一响应 Result<T> / 全局异常 / 参数校验 / JWT 拦截器 / 角色注解
   ▼
MySQL 8  (12 tables + 2 views)
```

后端包结构：

```
com.exam
├── common/        Result, PageResult, BizException, GlobalExceptionHandler, JwtUtil, @RequireRole
├── config/        MybatisPlusConfig(分页+自动填充), WebMvcConfig(拦截器+CORS), JacksonConfig
├── entity/        12 张表对应实体（含 deleted/createTime/updateTime）
├── mapper/        BaseMapper + 手写统计 SQL
├── service/       impl 分层，事务边界在此
├── controller/    Auth, User, Role, Category, Question, Paper, Exam, Answer, Grading, Score, Stat, Import
└── dto/ vo/       请求/响应对象，避免实体外泄
```

统一响应：`{ "code": 0, "message": "ok", "data": ... }`；业务错误码分段（1xxx 用户、2xxx 题库、3xxx 试卷、4xxx 考试、5xxx 判分）。

## 5. 数据库设计

### 5.1 实体关系

```
sys_user ─┬─ sys_user_role ─── sys_role
          │
qz_category ──(parent_id 自关联)
   └── qz_question ──┐
                     ├── ex_paper_question ── ex_paper ── ex_exam ──┬── an_exam_record ── an_answer_item
                     │                                    (考生范围)│
                                                                     └── sys_op_log
```

### 5.2 表清单（12 张）

| # | 表名 | 说明 | 关键约束 |
| --- | --- | --- | --- |
| 1 | `sys_user` | 用户（管理员/教师/学生） | `uk_username`，`deleted` 逻辑删 |
| 2 | `sys_role` | 角色 | `uk_code`（ADMIN/TEACHER/STUDENT） |
| 3 | `sys_user_role` | 用户-角色 | `uk_user_role` |
| 4 | `qz_category` | 题库分类树 | `idx_parent` |
| 5 | `qz_question` | 题目 | `idx_cat_type_diff`，`options JSON` |
| 6 | `ex_paper` | 试卷 | `idx_creator_status` |
| 7 | `ex_paper_question` | 试卷题目（含题目内容快照） | `uk_paper_question`，`idx_paper_sort` |
| 8 | `ex_exam` | 考试场次 | `idx_time_range`，`idx_paper` |
| 9 | `ex_exam_class` | 考试-可见班级范围 | `uk_exam_class` |
| 10 | `an_exam_record` | 答卷主表（一次作答） | `uk_exam_user_attempt`，`idx_user_status` |
| 11 | `an_answer_item` | 每题作答明细 | `idx_record`，`idx_review_status` |
| 12 | `sys_op_log` | 登录与关键操作日志 | `idx_user_time` |

视图：`v_question_accuracy`（每题正确率/难度/区分度）、`v_score_distribution`（分数段）。

### 5.3 核心字段（节选，DDL 到 M1 阶段落地）

```sql
-- 题目：选项与答案用 JSON，避免为 ABCD 单独建表
CREATE TABLE qz_question (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  category_id BIGINT NOT NULL,
  q_type TINYINT NOT NULL COMMENT '1单选 2多选 3判断 4填空 5简答',
  content TEXT NOT NULL,
  options JSON COMMENT '[{"key":"A","text":"..."}]，判断/简答为 NULL',
  answer JSON NOT NULL COMMENT '单选["A"] 多选["A","C"] 判断["T"] 填空["答案1","答案2"] 简答参考答案',
  analysis TEXT,
  difficulty TINYINT NOT NULL DEFAULT 3 COMMENT '1易-5难',
  score DECIMAL(5,1) NOT NULL DEFAULT 2.0,
  status TINYINT NOT NULL DEFAULT 1,
  creator_id BIGINT NOT NULL,
  use_count INT NOT NULL DEFAULT 0,
  create_time DATETIME, update_time DATETIME, deleted TINYINT DEFAULT 0,
  KEY idx_cat_type_diff (category_id, q_type, difficulty)
);

-- 答卷主表：计时与判分状态都落这里，服务端权威
CREATE TABLE an_exam_record (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  exam_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,
  attempt_no INT NOT NULL DEFAULT 1,
  start_time DATETIME NOT NULL,
  deadline_time DATETIME NOT NULL COMMENT 'start + duration，强制交卷依据',
  submit_time DATETIME,
  question_order JSON COMMENT '乱序后的题号顺序，续考时还原',
  objective_score DECIMAL(6,1), subjective_score DECIMAL(6,1), total_score DECIMAL(6,1),
  pass_flag TINYINT, status TINYINT NOT NULL COMMENT '0作答中 1待阅卷 2已完成 3超时强制交卷',
  switch_count INT DEFAULT 0, client_ip VARCHAR(50),
  UNIQUE KEY uk_exam_user_attempt (exam_id, user_id, attempt_no),
  KEY idx_user_status (user_id, status)
);
```

### 5.4 判分规则（写进 service 单测）

| 题型 | 判分 |
| --- | --- |
| 单选 / 判断 | 完全相等得满分 |
| 多选 | 全对满分；可配置「漏选且无错选得半分」；有错选 0 分 |
| 填空 | 逐空比对，trim + 忽略大小写；一空多答案时命中任一即可；多空按空均分 |
| 简答 | 不自动判分，置 `status=1` 进阅卷队列 |

## 7. 前端设计

### 7.1 路由表

```
/login                          登录
/student
  /student/exams                我的考试（未开始/进行中/已结束）
  /student/take/:examId         ★ 答题页（全屏、无侧栏）
  /student/result/:recordId     成绩单
  /student/scores               我的成绩
  /student/analysis             我的学习分析
/
  /admin/dashboard              工作台（统计卡片 + 近期考试）
  /admin/users                  用户中心
  /admin/questions              题库管理（左树右列表）
  /admin/papers                 试卷列表
  /admin/papers/edit/:id?       ★ 组卷页（选题 + 分值 + 排序）
  /admin/exams                  考试管理
  /admin/grading                ★ 阅卷台
  /admin/scores                 成绩管理
  /admin/stats                  统计分析
```

路由守卫：无 token → `/login`；token 解析角色后按 `meta.roles` 校验，越权 403 页；答题页 `beforeunload` 提示但**不允许**靠它防作弊（切屏由 `visibilitychange` 上报后端）。

### 7.2 组件与状态

- Pinia：`useUserStore`（token、profile、menus）、`useExamStore`（当前 record、答案草稿 Map、剩余秒数、答题卡状态）、`useDictStore`（题型/难度枚举）
- 复用组件：`TablePage`（搜索+表格+分页）、`CategoryTree`、`QuestionCard`、`QuestionForm`（按题型动态切换选项编辑器）、`AnswerSheet`（答题卡）、`CountdownTimer`、`ScoreBar`
- API 层按模块拆 `src/api/*.js`，页面不直接调 axios

### 7.3 视觉基线

Element Plus 只做骨架，主题变量覆盖成自定义纸白/墨蓝一套，每个模块一个强调色；统计页用真数据图表，不做「同一数据表格 + 卡片渲染两遍」；界面上不出现任何调试性文案。

## 8. Docker 化交付

`docker-compose.yml` 三服务：

| 服务 | 镜像 | 端口 | 要点 |
| --- | --- | --- | --- |
| `mysql` | `mysql:8.0` | 3306 | `--character-set-server=utf8mb4`，挂载 `db/*.sql` 到 `/docker-entrypoint-initdb.d`（首次自动建表 + 灌演示数据），`healthcheck` mysqladmin ping |
| `backend` | 多阶段：`maven:3.9-eclipse-temurin-17` 构建 → `eclipse-temurin:17-jre` 运行 | 8081 | 依赖 `mysql` healthy 才启动；`SPRING_DATASOURCE_URL=jdbc:mysql://mysql:3306/exam_db?...&serverTimezone=Asia/Shanghai`；`JAVA_TOOL_OPTIONS=-Duser.timezone=Asia/Shanghai` |
| `web` | 多阶段：`node:22-alpine` 构建 → `nginx:alpine` | 8080→80 | `location /api/ { proxy_pass http://backend:8081; }`，SPA `try_files` 回退 index.html |

- 开发模式：`docker compose -f docker-compose.dev.yml up`，后端挂载源码 + `spring-boot-devtools`，前端容器内跑 `vite --host 0.0.0.0 --port 5173`，改代码热更新，无需本机装 JDK/Node
- 已确认可用：本机 Docker 29.7.2 在跑，`maven:3.9-eclipse-temurin-17`、`mysql:latest`、`node:22-alpine`、`nginx` 镜像本地已有
- 数据持久化：named volume `exam-mysql-data`；演示重置用 `docker compose down -v`

| M6 | 成绩 + 阅卷：客观题自动判分、多选/填空规则、主观题阅卷台、成绩明细、成绩发布 | `/admin/grading`、`/student/result` | 5 份答卷判分正确，主观题给分后总分自动合并；未发布前学生看不到分 |
| M7 | 统计分析：教师看板、正确率/分数段/区分度、学生趋势雷达 + ECharts | `/admin/stats`、`/student/analysis` | 数字与 SQL 手工核对一致，无空图表 |
| M8 | 打磨与验收：全局异常与空态、导出、Swagger、日志、README、答辩演示脚本、全量回归 | 交付包 | 见 §11 验收清单全绿 |

依赖顺序：M1 → M2 → M3 → M4 → M5 → M6 → M7。若时间紧，M7 砍「学生端能力雷达」保留教师端看板；M3 的批量导入可降级为「前端粘贴解析」。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本机无 JDK，学校环境可能要求 JDK8 | SpringBoot 3 跑不起来 | 主方案 SB3 + JDK17（Docker 内跑）；准备 SB2.7.18 + MyBatis-Plus 3.5.3 + JDK8 降级清单，改动集中在 pom 与 `javax→jakarta` |
| MyBatis-Plus 与 SB3 版本不匹配 | 启动报 Bean 缺失 | 固定用 `mybatis-plus-spring-boot3-starter`，M0 阶段先跑通再往下写 |
| MySQL 时区/字符集导致时间与中文错乱 | 倒计时、成绩时间显示异常 | DDL 层 `utf8mb4`；连接串 `serverTimezone=Asia/Shanghai`；容器 `-Duser.timezone`；DB 与 JVM 同时设 |
| 客户端时间不可信 | 学生改本地时间作弊 | 计时与死线全在后端（`deadline_time`），前端只展示；每次保存带服务端剩余秒数回写 |
| 答题中途网络断开 | 答案丢失 | 答案先入前端 Map，恢复后重放；后端每次保存幂等（`record_id + pq_id` upsert） |
| 已发布试卷被题库改动 | 历史成绩失真 | §5.1 的入卷快照策略 |
| 判分边界（多选/填空）易错 | 成绩错，答辩现场翻车 | M6 写 service 单测覆盖 4 类题型 × 正误组合，判分逻辑不写在 controller |
| Docker 首次构建拉镜像慢 | 交付当天卡住 | 提前用国内 registry mirror，镜像层缓存；`mvn dependency` 层单独 COPY pom.xml 预热 |
